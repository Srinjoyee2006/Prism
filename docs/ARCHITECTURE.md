# System Architecture: Interruptible Voice Agent with Tool Commit Gate

Designed for **Full-Duplex-Bench v3** evaluation.

---

## 1. Full-Duplex Problem Statement

In standard half-duplex voice bots (turn-based walkie-talkie style), the agent locks the channel while speaking:
1. User speaks -> Silence detected -> Transcribe (ASR) -> LLM generation -> Speech output (TTS).
2. If the user starts talking while the agent is speaking, the user is ignored or audio collides.

In **Full-Duplex** voice communication:
- Both listening and speaking streams are continuously open.
- The user can barge in (interrupt) at any millisecond.
- The agent must detect user speech onset via low-latency VAD (Voice Activity Detection) and immediately cut off playback, abort in-flight LLM token generation, and flush all pending audio buffers.

---

## 2. The Tool Commit Problem in Full-Duplex Agents

When an LLM has access to tools (e.g. database mutations, bookings, calendar events), conversational speech poses a critical problem:
- **Speech is tentative and iterative**: Users often change their mind mid-sentence:
  > *"Please cancel my appointment for Monday... actually wait, make that Tuesday."*
- If the agent commits a tool call immediately when generated by the LLM stream, irreversible actions take place prematurely before the user finishes their clarification or barge-in.
- **The Solution: Tool Commit Gate**:
  - **Stage**: Tool calls are held in a staged queue rather than executed immediately.
  - **Acknowledge**: The agent begins a verbal acknowledgment (e.g., *"Rescheduling your appointment to Monday..."*).
  - **Gate Rule**: If the user interrupts during acknowledgment or before the stabilization window expires, the staged call is **invalidated/rolled back**.
  - **Commit**: The tool is executed only after user pause or verbal confirmation is finalized.

## 3. Subsystem Breakdown (Zero-Cost Local Stack)

```
 [Microphone Stream (16kHz)] 
            │
            ▼
┌──────────────────────────┐
│  VAD (Silero ONNX / CPU) │ ──(User speaking detected)──┐
└───────────┬──────────────┘                             │ [BARGE-IN SIGNAL]
            │ (Speech Chunks)                            ▼
            ▼                              ┌──────────────────────────┐
┌──────────────────────────┐               │  Interruption Controller │
│ ASR (faster-whisper int8)│               │  - Cancel TTS playback   │
└───────────┬──────────────┘               │  - Flush audio queues    │
            │ (Transcribed Text)           │  - Invalidate Staged Tool│
            ▼                              └──────────────────────────┘
┌──────────────────────────┐                             ▲
│  LLM (Ollama / Local)    │                             │
└─────┬──────────────┬─────┘                             │
      │ (Text)       │ (Tool Request)                    │
      ▼              ▼                                   │
┌───────────┐  ┌──────────────────────────────────┐      │
│ TTS Stream│  │       Tool Commit Gate           │      │
│(edge-tts) │  │ - Staged -> Verify -> Commit     │──────┘
└─────┬─────┘  └──────────────────────────────────┘
      │
      ▼
 [Speaker Output Stream]
```

1. **Audio I/O**: `sounddevice` ring buffers for continuous non-blocking input/output.
2. **VAD**: `Silero VAD` running on CPU via `onnxruntime` (~1ms per 32ms frame).
3. **ASR**: `faster-whisper` (CTranslate2 int8) for low-latency streaming transcription on 4-core CPU.
4. **LLM**: Local `Ollama` running quantized models (`qwen2.5:1.5b` or `llama3.2:3b`) with native function calling.
5. **TTS**: `edge-tts` (zero-cost neural voice streaming) with local `pyttsx3` fallback.
6. **Tool Commit Gate**: State machine handling staging, confirmation windows, and rollback on barge-in.
